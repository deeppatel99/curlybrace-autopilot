- [severity: medium] [location: section "The wrong choice, and what it costs", second paragraph] This presents the stale read as a result of Azure SQL's RCSI default. On any SQL Server, a plain `SELECT` running at locking READ COMMITTED takes a shared lock, and shared locks are compatible with update locks. So the path without the hint is never blocked by `UPDLOCK`, with or without RCSI. RCSI adds one thing: the reader also skips waiting on the *exclusive* lock after the other session has written. As written, readers on on-premises SQL Server will think they are safe. -> Rewrite: "Update locks don't block plain readers on any SQL Server, because S and U are compatible. On Azure SQL Database, where `READ_COMMITTED_SNAPSHOT` is on by default, the unhinted read doesn't even wait for the other session's uncommitted write. Either way, it reads the old value and overwrites."
- [severity: medium] [location: section "Nothing in your code threw" / "Do this today"] The hook names the root cause precisely: `Update()` writes every column. But the article never says the most direct fix. If the warehouse loads the entity tracked and sets only `Status`, EF writes only `Status`, and in this scenario the address is not lost. Later, in "It protects the whole row", rowversion causes a false conflict between exactly these two writers. A senior reader will notice that the recommended default turns this bug into retry traffic, while a one-line change prevents it. -> Add two sentences after the hook's diagnosis: "First, stop calling `Update()` on mapped entities. ## Fact-check notes for the author
- `HOLDLOCK` is equivalent to `SERIALIZABLE` and holds shared locks until the transaction completes -> VERIFIED https://learn.microsoft.com/en-us/sql/t-sql/queries/hints-transact-sql-table
- `UPDLOCK` "Specifies that update locks are to be taken and held until the transaction completes" (quoted correctly) -> VERIFIED https://learn.microsoft.com/en-us/sql/t-sql/queries/hints-transact-sql-table
- U locks are incompatible with each other, and S and U are compatible (plain readers aren't blocked) -> VERIFIED (lock compatibility matrix) https://learn.microsoft.com/en-us/sql/relational-databases/sql-server-transaction-locking-and-row-versioning-guide
- The rowversion storage size is 8 bytes, and the value changes on any update to the row, even one that doesn't change any values -> VERIFIED https://learn.microsoft.com/en-us/sql/t-sql/data-types/rowversion-transact-sql
